## v1.3 — sign in the familiar way

Use your existing master email address and nickname **Sean**. No User IDs to copy, device approvals, Google sign-in, passwords, Firestore setup, or imported scores.

Enable **Anonymous Authentication** in Firebase project **james-game-center**, publish the **personalized v1.3 Realtime Database rules supplied privately to the owner**, then press **Sign in** on the website. The app automatically creates the one **Sean · Master** player at `jamesV1/members/sean`, with zero scores. The same pair opens the same account on another browser; no extra authorization codes.

[Complete setup instructions](https://github.com/seansommer/James-Hulk-Racer/blob/main/docs/PLAYER_CENTER.md)

The public `firebase-database.rules.json` generated by the build is a safe TEMPLATE, not the owner's personalized copy. It has `OWNER_LOGIN_KEY_GOES_HERE` and cannot activate a new master. Do not put the owner's email, matching key or personalized rule file into public GitHub or assets. Use the privately supplied rules in the Firebase Rules tab. Publishing website code does not publish Firebase console rules.

## Your player features remain

The Hall of Fame has six trophy categories with tied rankings and separate Little Hero/Superhero records. Player Cards show nicknames, roles, lifetime and per-world records. The personal trophy room, three world links, game artwork, sound settings and mobile layouts remain.

Only Sean is created initially. Leave **Add a player later** closed. To add another player later, the master enters their email and nickname in that form. No browser User ID is needed. No family/SUJA accounts or scores are imported.

This uses the requested trust-based family sign-in. Anyone who knows an account's matching email/nickname pair can use it, including Master access. It is not verified email authentication. Raw email addresses are not stored in the game database or shown on Player Cards.

## Fresh records

Only `https://james-game-center-default-rtdb.firebaseio.com/`, namespace `jamesV1`, is used. Previous experimental root records remain untouched and do not appear in the roster. No Firestore data or scores are migrated. Practice and registered records are separate. Signed-in race receipts are immutable and retry-safe; scores remain client-measured for friendly competition.

## Development

The `shared-racer` submodule pins the exact shared account and game modules. Clone with `--recurse-submodules`, then run `npm install`, `npm run build`, and `npm run test:browser`. GitHub Pages uses **Settings → Pages → Source → GitHub Actions** in both repositories.

Security tests in the racer use a demo database and dummy email/nickname pair. Browser tests use fixtures, not live accounts. Live sign-in needs the owner to publish the personalized rules. Physical Safari testing remains separate.
